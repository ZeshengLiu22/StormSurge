Resource and runtime limitations
-------------------------------
Syntax and dry runs do not validate scheduler admission, a GPU allocation, CUDA
driver execution, NCCL collectives, GPU memory peak, throughput or convergence.
Runtime preflight in each PBS checks exactly four visible GPUs and NCCL support;
it is skipped in DRY_RUN. CUDA_VISIBLE_DEVICES is respected, not forced to 0-3.
The existing torchrun launcher uses a random local rendezvous port; rare port
collisions remain possible. No extra MPI process layer is introduced.

Each station has 36 year shards, approximately 3.35 GiB serialized. Samples have
a 29x32 grid (928 nodes), five raw source features and six target values. The
four DDP ranks load their own data, so host-memory use is replicated; serialized
file size is not a resident-memory bound. Temporal models retain seven frames,
and ConvLSTM keeps full-grid recurrent states before pooling. Actual memory
peaks, especially the V100's 32 GiB device limit, need the user's pilot run.
Batch size, history, pooling, hidden dimensions and preprocessing were not reduced.

Existing local timing reference:
PBS-launcher/architecture_avgrank_multiseed/README.md and experiments.py report
32.251-46.727 minutes for four sequential 300-epoch station runs of RELATED
PACT/CNN architectures on Derecho. These are historical documented estimates,
not measurements of the seven new shallow baselines and not Casper benchmarks.
One hour is plausible for faster baselines, but is not established for every
model. It allows 15 minutes per station, or 3 seconds per epoch before startup,
data loading, validation, final evaluation and output costs. ConvLSTM is the
largest runtime uncertainty. The requested walltimes were left unchanged.
